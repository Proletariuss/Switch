# Iteration 496：N待归档与保留任务修复，3.35阶段发行

2026-10-14。本轮补齐原生N待的Profile短信归档、保留启动任务与真实清理结果，新增可调用的Rust N待管理器和只读卡片清单能力。Rust全量2706通过/0失败/6忽略（daemon 1976/0/3），Go vet/test、Swift BLE 38组、12组协议差分、45项扫描器自测通过。公共N待尚未切换到新管理器，普通原生默认开关仍关闭；本轮不增加全Rust完成率。

## 本轮变更

- 原生N待收件进入既有Profile账本，复用去重、分段和转发链；只有持久提交后才发送SIP成功响应与RP-ACK。归档失败会退出对应故障会话，其他Profile保持独立。普通读卡器短信归档保持原行为。
- 启动等待者取消后，仍保留真实卡片工作任务；准备失败、自然退出和关闭都依据实际join与清理结果。未确认的物理工作不能被超时或已取消的界面等待者当成完成。
- 新类型化管理器复用原N待desired、claim-next/outcome、运行报告和重试账本。发送不确定或部分成功保持unknown，不自动重放。重试标识遵守既有48位十六进制格式。
- 新私有只读清单端点复用Rust的AID/EID/Profile读取，绑定当前读卡器代次，取消也等待实际APDU完成。未接管现有公开清单入口。
- PC/SC丢失回执绑定确切物理会话，并在presence ACK后保留。仅逻辑离线、关闭失败或尚有工作任务不能释放父归属；BLE仍要求后续专用物理关闭证明。
