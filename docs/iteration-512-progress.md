# Iteration 512：退出清理、物理完成凭据与关闭日志管道

2026-10-16。继续在Switch_MAC内加固原生后端的正常退出及异常退出。Rust已接管全部294条接口，Go源码、默认构建与运行依赖已经退出；本轮不增加接口接管计数，也不把软件回归等同于实体设备或运营商验收。

## 本轮变化

- 把启动前置校验、监听失败、父进程退出和信号退出纳入同一清理流程。共有会话恢复之后，模块、读卡器、QMI等独立资源分别清理；历史归档报错会记录并上报，同时继续清理已确认可释放的独立资源。
- 退出操作等待实际资源完成凭据。PC/SC、串口Close、短信接收任务、QMI关闭和启动任务、通话及射频恢复均保留完成结果。取消请求等待者不会丢失真实任务；句柄已经取走或任务panic不能被当作清理成功。结果未知时保留所有权与隔离状态，不重放物理指令。
- 最终通话模式恢复等待已接受的文件、射频和ADB占用释放，避免一次临时busy使最终清理永久遗漏；常态业务的即时准入和超时行为保留。QMI服务启动或CTL_SYNC失败时同步保留清理错误，未确认关闭时停止进一步探测。
- 清理入口先保持既有路由、凭证、原生所有权和允许操作检查，再取得退出许可；许可由保留的实际处理任务持有。最终入口关闭会等待已接受操作完成。退休路由继续404、活跃未授权请求继续401，关闭后已授权请求503，均不得写归档。
- 归档执行器追踪被取消等待者遗留的真实阻塞写任务，最终退出会等待写入并记录未交付错误。关闭stdout/stderr或日志写失败不再导致退出过程panic。
