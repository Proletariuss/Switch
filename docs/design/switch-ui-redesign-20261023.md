# Switch macOS 全新 UI 与交互设计方案

日期：2026-10-23。状态：**设计提案，待确认；没有修改现役产品界面、Rust 接口或操作行为。**

本方案基于当前 Switch_MAC SwiftUI 源码、用户已确认的使用偏好、Apple HIG 和开源 macOS 客户端研究。交互预览全部使用示例数据，不代表设备状态、真实收信或联网验收。

## 1. 推荐方向

采用 **Apple 原生通信工作台**：统一窗口背景、轻量侧栏、紧凑列表、按需展开的检查器。视觉参考 macOS Messages、Mail、System Settings 的信息组织；工程参考 CodeEdit、VirtualBuddy、Stats、CotEditor。品牌继续使用已有透明车环，固定容器内等比例完整显示。

重点是减少视觉负担，同时让用户清楚知道：当前控制哪台设备、哪张号卡；操作是否被后台接收；是否真正生效；失败后能做什么。

### 当前源码发现

- `ContentView.swift` 已有 NavigationSplitView、未读标记、隐私遮罩及通知跳转，可以保留。
- `GlassComponents.swift` 的 WorkspaceHero 仍组合英文 eyebrow、大标题、说明和 40pt 图标；与导航、卡片标题重复，增加顶部高度。
- 当前背景/卡片/边框具有较强蓝灰色差，许多状态与操作各占一张卡片；建议回到语义化系统颜色及行分组。
- 模块与读卡器已有共享 HomeView，适合统一设备详情框架，保留各自专有能力。
- 短信已统一来源，但来源标签、辅助操作、窄窗布局还可以收敛。
- 当前 Rust 后端已有较复杂的回执、占用和恢复语义。UI 改造应消费这些真实状态，而不是通过本地计时器猜测成功。

### 功能完整性约束

本方案调整位置与呈现，既有能力须逐项映射到新入口。除了下文重点流程，还必须保留：模块飞行模式、流量与4G出口检查、短信接管/存储/通知、模块 eSIM；BLE 凭据、Profile 重命名/过滤及运营商通知；N待全部/单条/多选操作、分页、运行记录及过夜统计；短信草稿、存储健康、单条/会话/设备范围删除；通话三种来源选择、DTMF、最近/完整历史、铃声试听、运行时准备/下载及配置备份还原；AT 调试、代理 UDP 诊断、部分采集结果和事件导出。低频维护放检查器或设置，不直接删掉。

第一轮优先做已有能力的布局与文案重排。应用内麦克风静音、音频设备选择、全局命令面板以及尚不存在的持久活动历史属于新增能力，必须独立实现并验收，不能在界面上摆出可用状态。

## 2. 信息架构与窗口

保留现有熟悉入口，第一阶段不强行合并模块/读卡器：

| 分组 | 入口 | 页面职责 |
|---|---|---|
| 概览 | 活动 | 显示需要处理的异常、近期任务和通信活动 |
| 设备 | 模块、读卡器 | 设备连接、当前号卡、网络和 eSIM 操作 |
| 通信 | N 待、短信中心、通话 | 线路管理、消息和语音 |
| 工具 | 诊断 | 按问题查看证据与恢复入口 |

设置放在 macOS 应用菜单，支持 `⌘,`；可另提供侧栏底部的非关键设置入口。按既有要求不恢复“关于与更新”导航项；版本信息可放设置页脚，软件更新保留在应用菜单中。

窗口由左侧导航、主内容和可选右侧检查器组成。标题只在一个位置出现；不再在顶部叠加英文分类、大标题和重复说明。工具栏与内容使用同一视觉背景，保留原生窗口拖动区、红黄绿按钮和侧栏开关。滚动到顶部时不画一条独立厚色带；必要的系统滚动边缘效果由原生组件提供。

### 建议尺寸，均为设计初值而非 Apple 强制规定

| 元素 | 初始值 | 行为 |
|---|---:|---|
| 默认窗口 | 1180 × 780pt | 记住用户调整后的窗口与分栏宽度 |
| 最小支持窗口 | 900 × 600pt | 以目标系统、标题放大和真实内容复验为准 |
| 侧栏 | 200–240pt | 可拖动、隐藏；不随每次刷新抖动 |
| 详情检查器 | 280–340pt | 默认关闭；窄窗转 sheet |
| 主内容边距 | 20–24pt | 窄窗降至16pt，不缩小文字凑空间 |
| 普通列表行 | 44–52pt | N 待多字段行可56–64pt；支持紧凑密度 |
| 正文 / 次要文字 | 13–14 / 11–12pt | 使用系统字体，支持文字放大 |
| 工具栏图标 | 16–18pt | 相同视觉字重和20pt图标容器 |
| 工具栏点击区域 | 32 × 32pt | 图标按钮共用尺寸；粗指针/辅助模式放大 |
| 圆角 | 控件6–8，面板10–12pt | 优先系统控件实际外观，不硬压系统几何 |

宽窗可同时显示列表与检查器；窄窗优先保留当前任务，收起检查器、压缩非关键列，随后折叠侧栏。短信在窄窗进入会话后采用列表→详情导航，避免把会话列表叠在聊天顶部。大量内容在内容区滚动；不能为了“整页不滚动”裁掉 profile、缩成不可读文字或隐藏操作。

## 3. 视觉系统

- **底色**：使用系统 window/control/text/separator 语义颜色。深色采用中性石墨色；蓝色用于选中和主要操作，不给每张卡片染蓝。
- **材质**：侧栏和系统导航控件适度使用原生材质；短信正文、号码列表、日志保持清晰实体底。玻璃效果随系统和辅助功能变化，不做整页高成本模糊。
- **边界**：优先留白、分组标题和细分隔线；仅给独立任务或浮层加容器。删除“卡片里再套卡片”的常规结构。
- **图标**：功能采用 SF Symbols 同一字重。透明车环作为品牌例外保留，使用 `.scaledToFit()`，不裁切、不拉伸、不加色底。系统通知使用打包图标的等比例透明车环内容，外层形状由 macOS 决定，不能承诺通知框架完全无底。
- **颜色语义**：蓝=操作/选中，绿=近期已确认就绪，橙=等待核对/需关注，红=明确失败/破坏性操作。始终配文字或图形，不只用颜色。
- **动效**：优先系统动效。自定义 hover 约100–140ms、面板展开160–220ms，作为可调初值；不让动画阻塞输入。减少动态效果时去掉位移、脉冲与旋转。无常驻旋转车环、背景粒子或闪烁状态灯。
- **一致性**：所有页共用工具栏规格、图标对齐、状态标签和错误展示组件。不同动作通过语义区分，不靠尺寸混乱强调。

依据：Apple [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)、[Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)、[Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Motion](https://developer.apple.com/design/human-interface-guidelines/motion)、[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)。

## 4. 每页设计与操作动作

### 活动

取消装饰性大仪表盘。首屏优先显示“需要处理”项目，下面是按时间排序的任务和事件。正常时用一行表达设备、就绪线路与未读数量。后台长任务只占一个活动条，不弹多个提示。

- 单击事件：定位对应设备/线路/会话，并打开详情。
- 单击进行中任务：展开阶段、持续时间和可用动作。
- 无异常：安静显示“目前没有需要处理的事项”，不制造健康评分。
- 同一根因合并提示；恢复后保留历史结果，不持续弹 toast。
- 当前进程内事件与持久操作回执分开。事件列表只有有限容量且可随进程重启清空；涉及恢复的任务只取耐久回执。跨重启长期活动历史列为新增能力，不将当前事件缓存包装为永久审计。

### 模块

顶部一个设备身份行：`DJI 一代 · USB · 控制通道就绪`。核心内容按“连接与网络 → 当前号卡 → 更多设置”固定顺序排列，窗口变窄时不改变阅读顺序。

必须区分三组状态：USB/控制通道、蜂窝数据与主机网络接口、Wi-Fi Calling。Mac 能通过模块上网，不等于 AT/SIM/IMS 已就绪；Wi-Fi Calling 可用也不等于模块提供互联网出口。

- **网络操作**：显示“当前实际连接”和“已保存配置”。QCFG 修改如需重启，按钮应叫“设置开机启用/禁用”，提交成功显示“配置已保存，重启模块后生效”；不能显示为“已关闭网卡”。
- **立即停止上网**：只有后端具备可验证停止路径时才提供独立按钮。否则明确该能力尚不可用，不用改一个开关伪装。
- **重启模块**：单独的明确动作；若影响当前唯一上网路径，显示具体影响，等待用户实际触发，不自动断网。
- **射频占用**：标明被通话、鉴权、切卡或后台任务占用。允许等待的操作排队并显示原因，不重复下发。只读短任务与长期业务区别处理。
- **网络优先级**：移入检查器；支持拖动并提供键盘上移/下移，保存前展示变更。仅点击“应用”后提交。
- **Wi-Fi Calling**：连接、注册、可用分别展示，代理详情折叠；不要默认引导清空代理或绕过既有 DNS 路径。

### 读卡器与 eSIM

多个读卡器用紧凑列表，显示可理解名称，如 `9eSIM_B1 · 蓝牙`、`ESTKme-RED · USB`。UUID、VID/PID、APDU 诊断进入详情。扫描到不等于已连接，连接到不等于认证或号卡读取成功。

- **扫描**：按钮点击后显示真实扫描状态，已有设备保持可见；结束显示最后扫描时间。
- **连接**：按“连接 → 认证 → 读卡 → 就绪”反馈；可恢复问题保留原设备和请求。
- **Profile**：列表展示名称、号码尾号、启用状态；单击选中显示详情，双击只进入详情，绝不自动切卡。
- **切卡**：明确列出当前与目标号卡、会受影响的线路，提交后按实际读取结果确认。
- **下载**：输入激活码 → 解析与检查 → 展示可确认的运营商/大小/目标卡 → 明确下载。后端拿不到准确大小时显示“大小暂不可用”，不虚构进度或文件大小。已接受的写卡操作不能因关闭 sheet 被当作取消。
- **删除**：独立破坏性确认，写明不可恢复及恢复资料要求。不存在恢复保证时不提供假“撤销”。

### N 待

默认列表视图，替代每个号码一张大卡片。表格只保留用户常用字段：线路、状态、最近确认、续期计划、短信未读和操作。未确认的数据明确用“未提供/待核对”，不填假倒计时。

- 工具栏从左到右为当前读卡器、必要的状态过滤；右侧 **打开短信按钮在刷新左边**，随后更多操作。不提供无意义的“全部号卡”单选菜单。
- 单击一行：打开该线路检查器；查看运营商模板、续期记录、断线原因和操作进度。
- 启动：行内从待机进入准备/鉴权/注册，成功以后台注册和业务准备状态为准。
- 停止：显示“正在停止”；仅在后台提供明确恢复阶段时显示“正在恢复原号卡”，不按本地计时器补阶段。后台明确确认终态后才显示已停止；资源清理若未确认，继续显示待核对。
- 在线计数：完整 inventory 为分母，仅在后台运行、状态新鲜、`desiredState ∈ {keep_online,running}` 且 `smsReady=true` 时计短信就绪；不能只统计当前页，也不能将缺失状态当作已停止、将 accepted 当作在线。缺少新鲜度证据时展示最近确认，不维持无依据的绿色在线标记。
- 到期/掉线：展示“预计续期”“最近成功注册”“等待读卡器”“恢复中”等事实。注册租期有效不等于永久在线，更不等于短信已实测送达。
- 批量操作：先选行再出现动作条，逐行报告结果。竞争同一实体卡的鉴权由 Rust 调度，UI 不并发切卡。
- 风险提示用一条简短说明，详情可展开：**“请妥善保存 eSIM 恢复资料。频繁切卡、异常断电或写入失败可能导致 Profile 丢失或卡片异常；部分故障无法恢复。”** 不暗示普通使用一定导致芯片报废。
- 用户正在选中、阅读或操作的行不因后台排序自动跳走；新增/状态更新不抢焦点。

### 短信中心

采用 Mail/Messages 式会话列表＋聊天内容；来源统一，但内部仍保留线路与订阅身份以确保路由正确。首轮保留现有会话分组。同联系人跨线路汇总属于可选新增展示，完成身份隔离验收后才开放，不能更改消息归属；回复时必须明确发送线路。

- 不恢复顶部“发送短信”按钮。新会话从会话列表旁的轻量撰写入口或 `⌘N` 开始；发送只出现在底部编辑器。
- 消息气泡包裹正文，最大宽度约会话区68–72%且上限约560pt；padding 8–10pt、圆角12–14pt。短内容如“PAC”不设置宽高下限；时间与发送状态放气泡外的小字行，去掉每条重复的大号来源标签。
- 连续同方向消息分组；接收线路在会话标题和线路切换处可见，必要时在跨线路消息旁给紧凑标记。
- 用户在底部时新消息平滑跟随；正在读旧消息时不抢滚动位置，提供“有新消息”跳转提示。
- 复制验证码为明确点击动作，不自动复制、不自动打开链接。保留现有隐私遮罩范围：身份字段与通知可遮罩，进入会话仍可阅读正文。额外隐藏正文的“截图模式”属于可选新增，需独立定义范围和出口，不默认为现有隐私遮罩已经覆盖。
- 回复：正文输入、当前发送线路、发送按钮组成一行；建议新增/统一 `⌘Return` 发送、Return 换行，先核对既有输入行为再上线。发送快捷键偏好属于可选新增设置。
- **发送未确认**与明确失败分开。未确认项目首要动作是核对原请求；普通“重试”仅在后端明确允许时提供。保留现有“作为新短信发送”能力，但它是用户主动选择的新请求，需说明上一条可能已发送、有重复风险，绝不自动触发。重试使用刷新图标，必须有“重试发送”的 tooltip/VoiceOver 名称；核对使用检查状态图标，两者不能同一个无说明刷新按钮。
- 删除待确认记录不会撤销运营商侧已提交的短信。列表可移除/隐藏显示记录；后台去重与回执证据只按既有安全策略回收，未知结果不伪装已取消。
- 成功文案按证据分层：普通设备 accepted 为“通道已接受，未确认送达”；N待依据对应的真实发送/状态报告更新，只有确认送达依据时才显示“已送达”；转发通道的 delivered 仅为服务已接收，不能共用一个含义不明的绿勾。
- 清空、导出、转发设置进入更多菜单，批量删除先显示范围。尊重已有本地删除与设备删除不同能力，不能将它们合成一个含糊动作。
- 会话删除按已审阅的线路身份及精确消息快照执行，不退回按号码跨线路删除；执行期间的新入站消息不被旧删除动作顺带清掉。

### 短信转发

从短信中心工具栏打开 sheet，按 Telegram / Bark 分页。每个通道只有启用、目的地、发送策略、最近结果；高级参数折叠。

- Telegram 代理默认系统代理，支持自定义及显式选择直连；按系统代理发现结果显示当前方式，不能检测失败后悄悄直连。
- 保存与发送测试分离。“发送测试通知”明确说明会向配置目的地发送测试内容，不携带真实短信；用户点击才执行。
- 成功只表示服务端接受请求，不能宣称用户手机已收到。失败分成代理连接、凭据/目的地、服务限流与结果未确认；令牌脱敏。
- Bark 展示图标预览及合法性反馈，加密方式/密钥/IV 等按实际后端能力提供，不以开关外观代替加密实现；密钥默认隐藏。
- 待投递队列逐条显示确认状态和下一步，重试前防止重复通知；unknown 不自动重发。

### 通话

拨号、进行中、来电三个稳定布局。设备选择移到紧凑标题区。来电号码、状态、接听/拒接以同一中轴居中；接听与拒接同尺寸，间隔24pt。挂断居中，不随右侧详情宽度偏移。

- 支持 `+` 和国际前缀 `00` 的规范化；显示最终将拨出的号码。当地号码依据所选线路/运营商规则处理，不能一律强制加国家码；短号保留。
- “正在呼叫 → 振铃 → 已接通”只跟随 SIP/通话事件；接通不代表对方实际听到，媒体状态独立呈现。
- 正常通话首轮显示时长、当前音频路由、键盘、挂断。**通话麦克风静音和应用内音频设备选择为新增能力**，当前核实的是来电铃声设置/试听及系统默认音频设备；两者不能混用。新增控制完成后台/音频桥接线和验收后再开放。音质异常时展示“未收到音频/播放设备异常”，详情提供已具备的真实统计。
- 编码偏好为 EVS 优先、AMR-WB 兼容；同时显示实际协商编码。仅设置偏好不显示“正在使用 EVS”。无 AMR-NB/PCMA 开关。
- 来电在别页时用非遮挡来电条与系统通知；点击进入通话，不能因页面切换自动接听。点击接听后禁用重复提交直到真实结果。

### 诊断与设置

诊断按“当前问题 → 相关证据 → 可执行动作”组织，去掉多层横向 segmented。普通视图只讲原因和下一步，错误码/原始日志在检查器；可复制脱敏摘要、导出报告。日志使用有界滚动列表，选中内容不被实时刷新顶走。

保留现有菜单栏入口、信号和速率选项，确保静默启动后仍能打开主窗口；参考 Stats 增强简报布局。扩展设备/线路/未读摘要属于后续增强，不能以此延后或移除现有入口。系统通知点击应定位到准确线路与会话，不能只打开短信首页。

设置使用独立原生窗口，保留“通用／隐私”两页，删除装饰性大页头：通用包含外观跟随/浅色/深色、登录自启、静默启动、菜单栏信号与上下行显示；隐私保留身份与通知遮罩，并明确正文范围。系统级登录启动开关保存失败时回读真实状态并就地提示，不保留假开启。新快捷键偏好、截图模式单列后续增强。模块运行时准备与备份/导入/同模块还原/删除放模块检查器的维护区，来电铃声留通话设置入口；所有迁移入口加入功能映射验收。

## 5. 全局交互规则

| 动作 | 即时反馈 | 完成依据 | 异常处理 |
|---|---|---|---|
| 只读刷新 | 原数据显示最后更新时间，按钮忙碌 | 新快照到达 | 保留旧值并标“数据可能过期” |
| 开启 VoWiFi | 接收请求后显示具体阶段 | 原请求回执＋真实会话状态 | 超时转“结果待核对”，继续原 ID 查询 |
| 停止会话 | 显示停止/清理阶段 | 后台 owner 退出及资源释放 | 不因为前端等候结束就假装停止 |
| 修改模块网卡配置 | 显示正在保存 | 后端确认配置持久化 | 分离保存成功与重启后生效 |
| 删除本地数据 | 明确范围，执行中可离开 | 存储提交确认 | unknown 保留任务，不盲目再删 |
| 关闭详情/sheet | 界面退出 | 仅结束展示 | 已接受的后台任务留在活动中心 |
| 取消任务 | 仅在后端声明可取消时提供 | 收到取消和清理确认 | 否则显示“停止等待/返回”，明确仍在后台 |
| 程序重开 | 读取已有任务 | 原 ID 核对和数据恢复 | 未完成任务不重置为空闲、不自动重发 |

任务状态模型：空闲 → 提交中 → 已受理/执行中 → 成功 / 明确失败；“结果未确认”和“清理中”是独立状态。超时不是失败证据，按钮动画也不是成功证据。

若现有 Rust 接口没有提供阶段/取消能力/新鲜度等字段，先显示较粗但真实的状态；新增字段按兼容接口工作项实现，禁止在 Swift 中推测出事实。设备业务调度、协议会话、业务重试、持久化和恢复继续由现有 Rust owner 管理；SwiftUI负责展示、选择、导航和动画，Swift保留已有CoreAudio与BLE等平台桥接。本轮不借UI改造迁移底层所有权，不新增Go业务或Swift重复业务状态机。

## 7. 工程落地与验收

### 验收与收益阈值

以下是待测目标，不是已经取得的优化结果：

| 目标 | 基线与测量 | 通过标准 |
|---|---|---|
| 少重复、更紧凑 | 同窗口900×600/1180×780/1440×900对照截图 | 单一标题；1180×780 N待至少8条完整普通行，主要操作常驻 |
| 快速完成任务 | 同一用户完成连接、查状态、查看短信、回复、处理失败 | 常用任务可见入口，主要操作不超过3次定位点击；必要安全确认另计 |
| 发送气泡正常 | 1/3/20字、长URL、多行、中英混合 | 不拉伸、不强制胖气泡；正文与元信息不挤压 |
| 状态可信 | 注入超时、掉线、晚到回执、重开、清理失败 | 0处“未知→成功”猜测，0次 UI 自动重复业务提交 |
| 布局可用 | 窗口缩放、长号卡名、100/1000 profile样例 | 不遮挡核心操作，稳定选择/滚动；大列表按需加载 |
| 交互性能 | 冻结机器和数据，使用 Instruments 记录 p95、CPU、RSS | p95输入反馈目标≤100ms；不比基线明显退步；空闲无持续动画唤醒 |
| 性能优化值得做 | 同条件至少5轮，报告中位数/离散度与修复风险 | 只在存在用户可感知瓶颈且改善≥20%或达到预设体验门槛时引入复杂优化，否则保留简单实现 |
| 无障碍 | VoiceOver、全键盘、增加对比度/文字放大 | 核心动作均可完成；正文对比度目标≥4.5:1，关键非文本≥3:1 |

测量阈值需要随真实基线校准；不为了百分比增加高成本自绘控件、复杂缓存或重复状态源。纯视觉变化不触发不必要的后端重构。
