## 实现与边界

Rust 保留串口优先的选择规则，实际完成串口枚举、探测及句柄释放后才决定传输。确认无串口后由 Rust 接管 USB；一旦确定 USB，即使后续初始化需要重试，也不会重新探测并误选串口。USB 由独立 producer 管理，启动配置、射频 bootstrap、eSIM 预读及清理实际完成后，才为本次物理会话发布短信就绪。观察者取消或停止等待不会提前释放已经提交的物理任务。

兼容 Go 子进程在 managed USB 模式下不再执行 USB 打开、启动配置和 eSIM 预读。父进程在公开及私有入口拒绝该模式下 Go 对 USB、模块射频、串口 actor 与通话模式设备控制的请求，拒绝发生在正文解析和物理入队之前；serial、reader、QMI 的现有兼容路径仍保留。

Go 子进程退出先确认真正结束，再只撤销其自身 producer。已选择 USB 的原生物理会话、短信身份及原生会话不随 Go 代次轮换；兼容后端重试耗尽也不会使原生 API 整体退出。USB 的状态、健康和 eSIM 查询及操作观察不再等待 Go ready，读取与写入仍复用原有事务、射频保留及操作账本。

修复了新启动路径中设备未就绪时本机短信归档统计不可见的回归：没有有效 USB binding 时仅返回 LOCAL 数量，不探卡、不伪造 SIM 就绪；旧 producer、停止和未确认清理仍失败关闭。短信观察加入独立代次，设备重开、配置或接管变化后旧结果不能发布到新会话；归档入队、清理证明和持久发送结果规则保持。
