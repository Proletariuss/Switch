## 接管与等价行为

- 清单读取复用真实 AID/EID/Profile 工作流和原 Store 稳定身份算法，缓存绑定读卡器代次；有活动卡片池时只用相同代次缓存，避免再次抢占卡。启动恢复只选择当前观测到、未删除且持久期望为 keep_online 的同一卡片 Profile。
- 启停/重试保留原 client_request_id 幂等与执行前持久认领。重复请求不重复执行；明确未确认的命令或清理返回 unknown。共享任务计数覆盖认领、实际执行和终态写回，正常退出等待全部写回尝试结束。持续存储失败在重启后仍隔离为 unknown，不自动重放。
- 原生管理器区分永久故障和可重试故障，手工重试会取消未发布的旧启动并等待实际结束。批量停止即使部分持久写失败也清理所有已选会话；退出重试依据新的真实清理回执，不被历史 worker 错误永久阻塞。
- 定时通知区分 Accepted、Stale、Busy；只有前两者可完成相同 owner/generation/attempt 的持久期限，队列繁忙保留期限。注册到期展示来自实际授予租期，并随同连接 REGISTER 刷新更新；未修改原代理、DNS、运营商覆盖或语音编码策略。
- 状态保持既有 ready/starting/degraded/backoff 等词汇，号码优先使用已注册身份，再使用 SIM 冻结号码。实体启用状态优先采用当前代次元数据；无活动卡片池且缺少元数据时才使用实际清单结果。

## 资源与退出修复

Pool 回执分别表示恢复原 Profile、没有 Profile 操作、或已确认物理读卡器丢失。失败关闭、纯逻辑换代和 BLE 缺失物理证明均不能释放归属。PC/SC 恢复不会将旧 Profile 写到替换后的卡片。

交叉审查发现清单完成与丢失证明发布之间的竞态：原实现可能在证明稍晚到达时丢弃清理句柄。现保留读取任务与确切父归属，等待实际操作结束及对应物理回执；取消界面请求不会提前释放。释放后再次核验读卡器代次。应用退出先停止调度并等待已提交清单，再完成原生会话/卡片恢复、持久结果写回，最后关闭卡片服务和 PC/SC owner。

手工 eSIM 变更继续遵守现有 N待占用互斥要求；本轮没有悄悄改为强制切卡。普通原生 VoWiFi 的三个默认开关未改变。
