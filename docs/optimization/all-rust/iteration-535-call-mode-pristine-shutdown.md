# Iteration 535：只读通话模式探测后的 Rust 退出确认

日期：2026-10-18

## 问题与证据

已安装的旧 `switchd-rs` 在前端退出后仍由 PID 1 收养，占用原有 Unix socket。其最后一条日志反复等待“未找到支持的模块 USB ADB 接口”的通话模式清理。该数据目录只有空的 `call-mode-operation.lock` 和 `.module-adb-interface.lock`，没有模块备份或语音运行目录。源码核对确认：只读状态/就绪探测本身即可创建两个锁文件，而退出逻辑此前仅凭它们存在就认定曾修改设备，于无模块环境反复尝试 ADB 清理。

## 修复

- 新数据目录在没有旧锁、备份或语音运行目录时记录权限为 `0600` 的 `.call-mode-pristine-v1`，作为“尚未提交物理修改”的持久证据。只读探测生成空锁后，此证据仍有效；纯运行文件下载也不撤销它。
- 通话模式启用/还原/准备等物理操作在接受操作前撤销证据并同步目录；独立语音路由启动在接触 ADB 前同样撤销。若撤销失败，拒绝操作，避免设备修改后仍被视为原始状态。
- 退出仍优先依据已接受操作、活动任务、备份和明确的 ADB/语音状态执行清理。没有标记的旧目录或标记损坏的目录保持保守判定，不把历史不明锁直接认定为只读产物。

## 验证与边界

- 生命周期定向回归覆盖只读双锁、物理准入撤销、旧目录和备份证据。
- 独立启动真实 shipping `switchd-rs`，在隔离目录复现只读空锁足迹，GET 状态后发送 SIGTERM；进程零退出，socket 移除，日志包含原生清理完成回执。
- 本轮改动只修复新版启动且能建立原始证据的数据目录。已安装旧进程的历史锁没有可信来源证明，因此不会自动删除、重分类或强杀旧进程。
- 此项不改变 SIM World 的 ESP 回程问题；ESTKme-RED 实测仍为 IKE/EAP 成功、IMS TCP 建连超时、ESP 发出 8/入站 0。IMS 注册、短信、通话及长稳验收仍未完成。
