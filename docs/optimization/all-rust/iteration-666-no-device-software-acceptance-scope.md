# Iteration 666：无设备软件验收范围

日期：2026-10-22（Asia/Shanghai）。用户明确本轮不会接入 DJI 模块或读卡器，并要求在不接设备的情况下完成验收。本记录把本轮可完成的**软件发布验收**与仍需物理设备或外部服务的**产品验收**分开，防止离线夹具、模拟响应或静态代码检查被误写成实机通过。

## 软件验收必须满足

1. 当前源码的完整迁移门禁通过；后端公开接口均由 Rust 持有，Go 实现、Go 二进制和运行时回退为零。
2. B01–B12 有限缺陷清单逐项取得同一源码摘要的软件证据，状态只能写为 `SOFTWARE_CLOSED`。
3. eSIM、短信、VoWiFi、模块恢复、读卡器选择、BLE 协议和音频策略使用确定性夹具、故障注入、跨进程并发及崩溃恢复测试；未知提交结果不得自动重放。
4. 在隔离的冷构建胶囊内先运行完整软件门禁，再构建 Release App；产物审计须确认版本、源码摘要、签名、Rust daemon 和包内无 Go 后端。
5. 使用该冷构建产物内的真实 Rust daemon，在硬件拒绝沙箱中完成启动、鉴权、接口、并发、信号关闭、子进程回收和数据清理生命周期验证。
6. P6 合成数据与升级保护脚本通过其软件检查，但不得把明确排除的旧 3.42 回退写成完整 P6 通过。
7. 验收台账元数据与当前源码一致；整体验收分母仍未冻结，不授予功能叶子 PASS，也不声称产品完成。
8. 三位不同审议者按顺序复核同一组带哈希的证据。任一轮发现阻断缺陷时先修复并重跑证据，再从第一轮重新绑定审议。

最终软件证明由 `scripts/check-no-device-software-acceptance.py` 以 fail-closed 方式创建和复核。发行脚本只在显式提供该证明时进入 `no-device-software-release` 范围；生成的 manifest 必须保持 `product_acceptance_complete=false` 和 `device_acceptance=UNVERIFIED_EXCLUDED_BY_USER`。

## 本轮明确排除且保持未验证

- DJI USB/QMI/AT 的枚举、初始化、热插拔、真实读写和网络恢复；
- PC/SC、BLE、9eSIM 与实体 eSIM 的连接、EID/Profile 读取、切卡、下载和写卡；
- 真实运营商的 VoWiFi、IKE/IPsec、IMS 注册、短信收取/投递和呼入呼出；
- 实际麦克风权限、声卡路由、主观音质和长时间通话稳定性；
- Telegram、Bark 及代理网络的外部端到端送达；
- 旧 3.42 产品回退兼容性。

这些项目不再阻塞本轮的软件发布候选，但状态只能是“用户排除、未验证”，不能写为 N/A、PASS 或已完成。将来若重新要求产品实机验收，应使用同一已发布源码和明确的设备/卡/网络矩阵另开证据，不改写本轮记录。
