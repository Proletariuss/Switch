# Iteration 575：读卡器状态与短信转发持久化修复

2026-10-19。整体仍为P1–P4同步验收、P5完善、P6最终验收未完成。接口接管100%（294/294，含54条派生HEAD）单列；完整验收分母尚未冻结，不据测试数量换算整体百分比。本轮不生成DMG。

## 生产改动

读卡器信息将逻辑选择、系统卡片在位、MUTE/电源状态、会话及身份元数据就绪分别表达。PC/SC轮询仅查询状态，不打开、复位或向卡片发送APDU。信息与列表共用有界扫描池，两秒总预算包含排队；取消等待者不会提前释放仍在系统调用中的真实worker。缓存250毫秒且命中不延长有效期，迟到结果必须匹配选择、会话、身份和发布代次。

确认缺卡、读卡器消失、MUTE或可用插拔计数变化后，公开身份锁存失效，直到Gate原子发布新的物理读取结果。发布epoch与身份、选择和会话在同一锁中取得；仅补充电话号码、清空元数据或重放旧回执不能解除锁存。UNPOWERED单独表示卡在位但暂不可用，不推断换卡。被隐藏的旧身份不能通过号码备注、运营商或ePDG回填重新出现；私有读卡器生命周期事实、eUICC能力和worker归属不被只读接口销毁。

BLE桥连接不再虚构卡槽PRESENT。正常连接、已有物理读取身份和eUICC能力仍保留。聚合页面不会自动选择仅有unknown卡状态的BLE外设，显式手动连接保持可用；列表兼容回退仍有旧的首读卡器自动选择行为，本轮不声称所有回退路径均采用聚合选择规则。

Swift与Rust聚合DTO增加八个可选状态字段，旧响应仍可解码。未知或失败的信息观测撤回旧SIM、号码/运营商、ePDG与就绪展示，保留已知能力骨架。正在执行的VoWiFi操作使用独立的已确认身份绑定：短暂未知后同卡恢复不误结束操作，首次确认掉卡或换卡会拒绝旧完成结果，重复缺卡快照不会取消在该状态下后来发起的关闭操作。未知前已发出的GET不能借同卡恢复重新获得发布权限，下一次新聚合可恢复当前状态。

短信转发修复了真实重试缺口：首次defaults同步失败后，快照可能仍在内存；原缓存分支下次直接提交。现在缓存分支也必须确认synchronize成功，否则继续返回原snapshotPersistenceFailed，禁止提交且不重编码冻结快照。未更换生产存储实现或将同步结果伪造为成功。

- 唯一失败仍是常量PAC测试所需平台服务被原沙箱拒绝。仅针对该套件采用已核验的CFNetworkAgent服务许可后，6项通过。去重后3369个不同Rust用例有通过证据；不能把重跑6项全部另加。服务自身不继承测试进程的网络限制，不能据此证明任意PAC脚本没有网络行为。
- 完整Swift readiness入口通过，包括同卡恢复、确认中断、换卡、重复中断后的新stop、旧GET撤回、新聚合恢复、信息查询错误及手动BLE连接。两次新增fixture失败分别为漏填既有必需字段available和retryable，修正测试数据后通过，生产解码要求未放宽；原失败日志保留。
- 短信转发使用实际生产Store与仅恒返回false的同步故障子类：旧源码负控制稳定触发“缓存重试仍提交”，新源码连续两次阻止POST、只保留首次恢复GET、原快照字节不变。这个通过仅证明失败关闭，不能算作真实成功落盘或完整跨语言验收。
- API审查只更新已核对的7个生产作用域，新增presence模块的独立审查，共432项；294条接口均由Rust接管，0条Go归属。2891项编译/行为输入冻结，较574有17项变化（10个Rust、5个Swift、2个审查元数据输入）。

## 偏好存储实验取舍

完整Swift生成→Rust写回→Swift比较的1项必需前置仍未通过。严格fixture已要求首个错误必须是预期503，不能用宽泛catch掩盖真正的持久化失败。

保留原强沙箱的direct-mode与绝对domain探针均未证明实际落盘及独立进程恢复。绝对domain的两个精确平台服务对照中，writer的synchronize曾返回true，但目标plist仍不存在且独立reader不匹配，故整体仍判失败；不猜测域被清洗或数据存到了哪里。测试没有为真实Library或偏好daemon新增写权限，没有手写plist冒充Foundation持久化。停止继续扩大SPI、Mach或偏好目录权限的实验，转而修复上述可复现的生产重试缺口；完整成功路径保留待验收，不能豁免。
