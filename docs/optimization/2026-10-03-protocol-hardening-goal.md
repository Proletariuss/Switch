## Rust 边界

当前已存在 Rust IKE 建链/EAP-AKA、ESP、受保护 SIP REGISTER/连接机制与 smoltcp，不重新从零实现。原生运行接管仍缺完整 rekey/重新认证调度、最终会话 actor、SMS-only 在线业务和 N待硬件调度。普通 reader 的长期 lease 不能复制成每个 Profile 一份；多 Profile 必须共享每张实体卡的串行 AKA/切换 broker，而网络会话独立长期运行。

迁移不能用逐包 HTTP/JSON IPC 拆散 UDP/ESP/网络栈。未知短信不转给另一后端重试；回退须完成旧 owner 关闭。Rust 的 Send/Sync、async 锁不保证无死锁或业务原子性。来源：[Rust 并发说明](https://doc.rust-lang.org/book/ch16-03-shared-state.html)、[Tokio Mutex](https://docs.rs/tokio/latest/tokio/sync/struct.Mutex.html)、[IKE rekey 与重新认证](https://www.rfc-editor.org/rfc/rfc7296.html#section-2.8.3)。
