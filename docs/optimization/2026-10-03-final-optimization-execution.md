## 采用的实现

### C6 设备短信发送授权与身份隔离

设备 API 现支持 `client_request_id` 和 `expected_subscription_id`。`POST /api/sms/send-intents` 先登记固定目标/正文/来源与原通道绑定；`POST /api/sms/send` 只使用原始绑定。Rust 独立账本在文件锁、原子写入与持久确认成功后授予一次 claim；相同 ID 不同内容或身份拒绝。操作进入 submitting 后，无论丢响应、进程重启、归档错误或未知终态，都不重新授予同一请求。finish 需匹配原 attempt。旧无 ID 的调用仍可用，但丢失服务器生成的 ID 后不能靠它恢复，应用三个入口已全部升级。

Swift 恢复先列出持久请求；默认发送遇到已有未解决的同载荷请求只查询。prepared 且原通道仍有效时可点“继续原发送”；其他状态只查询。“新发送”会提示可能重复，必须重新明确选线。查询和生命周期都有代次保护，旧响应不能覆盖新操作。通道接受、归档确认、收件人送达分开表达；本轮未实现送达回执。

账本上限 10000 条/32 MiB，满后拒绝，不静默删旧请求授权。短信历史仍为 1000 条/8 MiB；清空历史不清空独立发送账本，界面说明该行为。账本保存明文正文且使用本机私有文件权限；这不是 Telegram/Bark 的加密队列，也不是加密备份。删除或人为替换整个账本不在防重复保证内。启动 recover 阶段若遇账本语义损坏或读取/持久化失败，Rust 服务拒绝启动，而不是只禁用短信发送；运行中 prepare/claim/finish 失败则拒绝该操作或保留 unknown。不存在自动删账本或自毁逻辑。有效旧快照被外部回滚也没有独立防回滚证明。

Go 捕获原 IMS session、modem 实例或 USB 实例，不把旧请求重新映射到当前设备。modem/USB 全多段发送持有协调锁，串行化不同短信发送及遵守同一协调锁的 SIM/手动 AT 操作；锁后再次检查原路由。modem 在实际队列执行及 prompt 后写 PDU 前复核已观测代次；USB 只具备已缓存身份元组，claim 前绑定有效期为 30 秒，已获 claim 的排队执行仍复核原实例与已观测身份。进程重启后的旧 prepared 不重建通道闭包。不能把这些保护描述为物理卡租约，未报告的热插拔仍不能完全识别。

新 IMS 收件身份仅来自安装回调时原会话完整匹配的 ICCID、IMSI、sessionKey，派生不含明文身份的订阅 token。迟到回调保持原来源；不按当前卡补旧历史、SM/ME 或缺证据消息。新稳定 ID 纳入订阅；新 ledger 发件再纳入 request ID，两个不同请求同毫秒也不会合并。Go/Rust 的兼容 ID 有同一固定哈希夹具，旧记录 ID 不变。

短信会话和通知按有证据的订阅隔离；旧卡历史不显示成新卡号码，未知历史标为未知。只有当前已就绪线路与历史订阅一致，才默认回复原线路；其他情况要求明确选线，已观测换卡使旧选择失效，草稿保留。普通 reader 身份观测失败同时撤销短信 ready。

### C10 只读 JSON 归档导出

短信中心新增与现有按钮同尺寸的导出入口，可按来源、设备/Profile/已知订阅、对方号码及时间选择。默认遮盖号码、正文、Profile/订阅标识和原消息 ID；用户可明确选择完整内容。输出有 schema、来源与截取时间、规范化消息和数量。只包含本机已保存的历史，不把页面已加载的部分当成全部，也不扫描真实号卡。

Rust 在各归档的既有锁下固定文件描述符，解除锁后顺序解析单条记录，文件替换不改变已固定的内容。两份来源是各自独立截面，不宣称跨库原子事务。设备 8 MiB、N待 64 MiB 输入界限；单条 1 MiB、输出 128 MiB；另保留最多 100 万个消息键（每键 ≤4 KiB）检查重复，不保存全部正文。最多四份导出，十分钟失效。导出文件为立即 unlink 的匿名 0600 文件描述符，后台定期释放过期句柄；不修改未读、通知、转发、changes 或权威档案。

App 每次只取 256 KiB，校验精确长度、偏移与 EOF，写用户选择路径旁的 0600 临时文件。同步、关闭、原子 rename 后同步目录。失败/取消清理临时文件与后端 token；无法 DELETE 时由 TTL 回收。rename 后目录同步失败明确报告“写入但确认不足”，不声称回滚原文件。HTML 与导入恢复本轮不采用，避免额外解析/执行面；JSON 导出不是完整应用数据恢复包。

### C11 AT 控制台正确性

旧实际 handler 可让控制字符进入传输层，组合命令后续不带 `AT` 前缀的操作也能绕过原飞行模式检查。新手动入口拒绝控制字符、跨行和超 4096 字节输入，解析组合命令时保留合法引号/分号及原始命令内容；对转义引号歧义作保守双解析。保持未知厂商高级命令可用，不把现有规则包装成全厂商安全沙箱。

协调锁等待使用一个 20 秒预算，取消尚在排队的操作不会迟到提交；拿到锁后重查 VoWiFi 与飞行模式所有权。已提交则等待原操作终态，不通过取消授权重复执行。API/UI 区分模块 ERROR/CME/CMS 与通道故障，保留原始响应，并在 AT 输入处显示具体操作影响。安全事件导出不附带原 AT 响应或协议正文。内置 eSIM 下载/认证命令路径不改。
