## 本轮源码优化：N 待短信转发持久确认

执行对象：[`代码库优化审查`](2026-10-02-codebase-optimization-review.md)中的 P0 转发可靠性项。实现前快照保存于 `build/optimization/2026-10-02-sms-forwarding-start/`：3,227 个源码/项目文件、50,841,372 字节；归档 SHA-256 `984037513060bd27ccff06514358b6c12980b9c7aee225d92c7dd9063555fb77`。版本仍为 2.74/build274。

- N 待短信使用独立的持久 changes cursor。转发在每次状态刷新中先于通知游标同步，以便首次启动先建立转发基线；旧安装则从已有通知游标衔接。短信正文不保存到 UserDefaults。
- 收到页内符合条件的入站短信后，应用等待 Go `/api/sms/forwarding/enqueue` 返回，再保存该页游标。页级批量最多 200 条；后端返回前会完成加密队列持久化。结果不明确或接收失败时保留游标，下次重试用同一稳定 ID；后端重启后的去重也有 Go 测试覆盖。
- 转发关闭期间继续推进游标，重新开启时先取当前高水位，避免突然补发停用期间的旧短信。若归档记录已被用户删除导致正文不可读，会显示提示并继续后续记录。
- 新增注入式转发接口和隔离故障测试，覆盖接收前失败、持久接收后响应丢失、重启重放、开关停用、启动基线、归档删除以及同页批量。测试明确验证两条短信通过一次页级 enqueue 提交；这证明请求合并行为，未代表实机网络时延数据。
- 扩展 Go 持久队列测试：重新打开加密状态后重放同一 ID，队列不重复。
