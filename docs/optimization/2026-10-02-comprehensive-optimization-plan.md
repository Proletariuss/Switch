# Switch 全面优化方案（2026-10-02）

## 目标与边界

这份方案以当前 Switch 2.74/build274 为基线，按“先测量，再判断是否值得改”的原则推进：每项候选先记录可复现基线、成功指标、实施成本和回退办法；达到收益门槛且没有稳定性、安全或业务回退，才改生产代码。未达到门槛就停止并记录原因。

工作范围仅限 `/Users/proletarius/Desktop/Switch/`。不改原始参考目录、不迁移整套架构、不批量删除恢复材料、不调高轮询频率，也不生成 DMG。本文是方案，不代表任何尚未进行的真机或运营商验收。

用户已明确要求后续不再处理 9eSIM 下载 `6982`：从优化候选中永久移除，不分析、不测试、不修改相关代码；旧记录仅供追溯。现有其他 VoWiFi、短信、通话、eSIM、N 待及 UI 行为作为回归保护范围；不重新引入已移除的传真功能。

## 目标指标和测量口径

所有比较固定在同一源码快照、Mac、Release/Debug 配置、工具链、设备与数据规模；保存原始样本、样本数、预热次数和 p50/p95。没有匹配的基线就先测，不先改代码。一次性正确性和隐私审查可以按风险缺陷处理，不伪装成性能收益。

| 领域 | 基线与测量方法 | 进入实施的收益门槛 / 验收线 |
| --- | --- | --- |
| 空闲资源 | App、Rust、Go 三进程合计 CPU、RSS、唤醒；前台和后台各 3 组 × 10 分钟；记录屏幕/网络/设备状态 | CPU 相对下降至少 20% 且绝对下降至少 0.5 个百分点，超过样本噪声；RSS 仅在出现可复现增长或资源压力时立项 |
| 短信中心 | 0/100/1000 条固定夹具分别测解码、分组、排序、刷新、首屏绘制、主线程等待；滚动另记录掉帧 | p95 至少改善 25% 且绝对节省至少 50 ms；不得增加消息发现延迟或漏项 |
| N 待会话 | 每个测试 Profile 记录启动、隧道/IMS/SMS 就绪、租约更新时间、心跳结果、失联、撤销 ready、恢复及首个成功 SMS 操作；统一时钟并脱敏 Profile ID | 显式断连后撤销 ready 的 p95 ≤3 秒；故障恢复按“故障到首个成功操作”报告分布。只有稳定复现且候选改善越过噪声才调 lease/重试；零串 Profile、零重复切卡写入 |
| 读卡器短信与 CPMS | 在同一读卡器、卡、固件及短信数量下统计 CPMS/APDU 次数、每次占用、串行队列 p95、新短信发现延迟 | 统计调用至少减少 80%，且资源或排队有可测收益；消息发现 p95 不得恶化超过 5% 或 250 ms（取较严格值） |
| 短信转发 | 本地假 Telegram/Bark 服务覆盖成功、超时、重试、进程重启、重复 ID、密钥错误；记录持久化接受时间、队列最老年龄、重试结果和重复投递 | 本机已接受的消息重启后仍可恢复，凭据不进日志/状态响应，去重规则有测试。远端在请求已送达但响应丢失时可能重复，不能承诺服务商提供 exactly-once；真实服务测试需账户/目标设备配置 |
| 页面交互 | 选模块、读卡器、短信中心、N 待和诊断页，记录首屏、页面切换、按钮响应和滚动帧时间；用代表性 5/20/50 Profile 与短信列表夹具 | 先以 p95 响应 <100 ms、滚动 95% 帧 ≤16.7 ms 为目标；只在重复测量有 >20% 且至少 8 ms 改善时做性能重构。纯视觉改动不作为性能优化 |

## 执行阶段与验收交付

1. **冻结基线：**新建只读测量记录，核对私有快照、应用版本、运行包位置、活动构建进程与磁盘清单；不结束当前应用、不触碰设备。
2. **低风险整理：**在源码中修正文档基线和构建说明；只做 `clean-generated.sh` dry-run 并汇报估算空间与保留项，不因“看起来多余”删源码或验证材料。
3. **离线测量：**用固定夹具补齐短信 UI、通知队列错误路径和页面响应指标；已有定向回归只在生产代码变化时重跑，避免无意义重复测试。
4. **受控运行测量：**只有在用户安排设备空闲窗口后采集短时资源和 VoWiFi/CPMS 样本；报告实测范围与样本数。不运行通宵、24 小时或百轮 soak。
5. **实施合格候选：**一次只改一个瓶颈，性能工程控制在 1 人日；严重正确性缺陷最多先做 2 人日最小修复，再重新评估。定向回归、隔离门禁及 Release 构建通过后更新前后对比和回退点；不生成 DMG。

每个候选的记录格式：问题证据、快照/设备条件、原始样本、基线 p50/p95、目标、工程与维护成本、实施差异、定向回归、风险/未测范围，以及“采用 / 停止 / 暂缓”的结论。连续两轮未越过收益门槛、收益落在噪声内、超过预算或出现业务退化，即停止该候选并保留取舍记录。

## 本次方案结论

当前有充分证据保留已经生效的短信解码优化；没有证据支持继续改短信分组、VoWiFi 心跳、CPMS 轮询或构建缓存。下一阶段最划算的是先核实应用包路径和版本文档，再用短时、可复现的 UI/资源测量决定是否继续。磁盘缓存清理可作为独立、分批且可重建的维护项，优化快照和用户数据不纳入清理范围。

本文件仅新增优化方案；未改生产代码、未运行真机业务、未清理缓存、未停止正在运行的 Switch，也未生成 DMG。
