# Iteration 089：模块短信通知与接收调度迁入 Rust

日期：2026-10-05。所有修改、缓存与模拟数据均在 Switch 内。未连接真实号卡、发送短信、拨打电话、启动生产 App、读取生产数据或生成 DMG。语音目标继续为 **EVS 优先、AMR 次选，不使用 PCMA**；当前实际主机能力仍为 AMR-NB，EVS/AMR-WB 未接入。

## 本轮实现

模块串口收到 `+CMTI` 时，Rust 串口 actor 直接建立接收任务，由一个后台 worker 调用 Rust typed ingest。任务复用原有 CPMS/CMGL 原子快照、TPDU/长短信解析、耐久归档及 ME 单条精确 PDU 复核删除，不再先让 Go 为每条通知启动读取协程。短信仍在原短信中心与原归档中呈现。

- 单串口 owner、单接收 worker，最多 64 个等待任务。同存储重复等待通知合并，满队列可合并成该存储的完整扫描；不跨存储覆盖任务，不把正在处理的索引当作已去重，以免漏掉同索引的新短信。无法入队时保留卡内来源并记录固定错误，不启动第二套 Go 接收链。
- 任务同时冻结 SIM generation、串口会话标识与接收配置代次。串口重开即使 wire generation 重新为 0，也不能复用旧任务；读、归档前确认、删除前及删除步骤均检查所属会话。关闭时撤销等待任务，正在执行的任务保持占用直至实际完成，期间拒绝重新打开端口。
- 串口打开只准备后台 worker，不立刻开启自动收件。Go Start 在启动 read/run loop 前明确配置禁用/自定义回调策略；首次启用接纳尚未交付的积压帧，后续切换不改变已经观察到的帧归属。Rust 已接管的 CMTI 帧附带标记，Go 仍可读取它，但不再重复触发收件；RING、USSD、SIM 等兼容事件保留。
- Go 保留模块初始化与 radio/占用协调；初始化完成或用户刷新后，只向新私有认证路由 `POST /api/internal/modem/sms-receive` 提交 scan，实际排队及代次捕获归 Rust。scan 保留原 CheckAllSMS 语义，自动接收禁用或自定义回调不禁止显式刷新；Go 的 busy 检查仍在。
- 配置确认丢失时 Go 关闭当前连接并标记不可用，不按旧状态重放或回退。健康/运行状态补充锁保护，旧兼容 CMTI 异步任务纳入等待，保证 race 测试与退出能够等到真实任务结束。
- daemon 终态退出先确认串口 Close，再等待接收 worker 真正结束；阻塞归档已启动时继续等待，不把 abort 当作磁盘操作完成。Close 使用可等待的有界 mailbox 入队及真实回复，不因普通 RPC 超时提前视作设备释放。Go 终止报错也先完成此收尾再传播错误。
- 已发出的 CMGD 遇到配置失效、直接关闭或断线时，保持 `delete_outcome_uncertain`；不会声称来源一定保留或删除成功。归档失败时完全不发送 CMGD，SM 和长短信来源继续保留原清理规则。

## 取舍与后续边界

Go-only 兼容实现与内部 `ingest-stored-sms` 端点暂留；后者沿用旧 generation-only 契约，新生产自动收件使用完整会话栅栏。USB 单独轮询、读卡器/IMS/N待短信生产、非短信 URC 业务分派、模块初始化及硬件线路桥尚未迁完，本轮不等于设备端到端无 Go。

现有无有效短信时间戳时使用当前时间的归档身份规则没有改动，重复扫描的稳定身份仍需单独评估。旧 HTTP open 回复丢失的端口归属问题也未用无条件 close 处理，以免关闭其他持有者；新 worker 在首次配置前不自动读卡，避免为旧问题增加后台副作用。归档本身失败不无限重试，保留来源供后续通知/显式刷新恢复。串口 actor 线程自身的最终 join、其他生产者排空、异常进程退出与实机长稳仍在后续范围。

本轮只将模块接收事件与调度的实现及离线证据计入P2B：**33.9% → 35%**，增量0.088计划人周。P2A维持59%，原47.5人周基线累计 **10.755 / 47.5 ≈ 22.6%**（估算误差约±3个百分点）。EVS新增平台/codec成本仍待试点后重估；22.6%只代表原迁移基线，不等于含新增范围的总目标完成率或可发布程度。政策修正、测试数量、路由数量均不独立增加迁移得分。

下一步继续收窄模块初始化/占用协调与非短信事件的Go依赖，并保持USB、读卡器和IMS各路径的真实归属边界；真实EVS codec接入按独立媒体能力门槛推进，不能用SDP名称或配置开关代替实现。
