# Iteration 510：生产 Go 进程与应用构建依赖退出

2026-10-16。生产启动、运行分发与应用打包现只使用 Rust 后端。本轮完整软件门禁、禁用 Go 编译器的应用构建、包内后端隔离启动与退出均通过；源码及测试工具链仍含 Go，不能宣称全项目迁移完成。

## 实现与行为

- 移除 Go 子进程启动、重启监督器及默认转发；未识别路由返回 404。六条剩余 Go 私有状态/短信桥退役，相关健康、状态、eSIM 与短信设备选择由原生持有者提供。串口选择优先且保持原设备，即使暂不可用也不改选 USB；旧 Go 事实不能改变实际设备选择。
- eSIM 本地操作账本和物理预约继续约束写卡。旧短信绑定在提交前明确失效，已提交/结果未知的意图保持原状态，不能自动重发。删除兼容分支没有取消身份、代次、射频恢复或耐久性校验。
- 保留显式 `-port` 与 `-backend=qmi` 参数。原生 QMI 初始化在受保留的工作者上执行，超时后的迟到句柄仍由该工作者关闭；接单、父进程监测与退出不被初始化阻塞。退出等待实际关闭。
- 修正无设备、从未启用通话模式时仍尝试 ADB 恢复导致的退出失败。仅明确没有操作历史、活跃工作、恢复状态或落盘恢复材料时走空清理；元数据不可读等不确定情况仍要求原清理流程。
- Xcode 构建脚本移除 Go 编译、嵌入和签名，仅构建 Rust 与必要 EVS C codec，保留 libusb 和许可资源。Swift 启动与状态标记同步为原生运行时；前端业务与界面没有重设计。

## 已验证证据

- Rust workspace **2936 通过 / 0 失败 / 7 忽略**，其中 daemon **2195/0/3**。实际后端进程测试 2 项覆盖无 Go 启动、SIGTERM 和父进程退出后的清理。
- Go vet/全包测试、两组 Swift BLE 检查（manager 39 组）及现有 13 组协议/适配差分通过。补充审计发现既有 SDP 组通过 Go 适配器调用 Rust 协商器，它只能证明适配一致，不能算独立 Go 协商结果；后续保留明确拒绝样例与已有 Rust 黄金测试，不夸大该组证据。
- 严格 Rust-only 契约检查通过：**294 条契约全部由 Rust 接管**、54 条 HEAD 别名、127 个 Swift HTTP 调用点、484 个审阅范围。47 项契约工具与 4 项退出工具自测通过。
- Xcode Release/arm64 应用构建通过，PATH 中 Go 被替换为一调用即报错的检查脚本，未触发。包内后端只有 `switchd-rs` 和 `libusb-1.0.0.dylib`，libusb 使用包内相对路径；完整签名校验通过。
- 直接运行新包内后端，使用独立数据目录和不存在的显式串口，确认原生运行时、无设备状态、无 Go socket、正常退出与全部 socket 删除。没有启动用户安装的应用或选择实体卡。
- **4145 个冻结构建输入文件零漂移**。构建期间仅三个 Go 测试文件发生修正，应用/Rust/native/resource/build 输入一致。失败和修复日志保留，未用旧成功输出覆盖失败。

## 尚未完成与下一步

旧退出扫描器只统计 197 个 Go 生产文件；完整审计为 **493 个非测试 Go 文件、361 个测试文件、5 个 Go 模块**。构建与运行已经脱离 Go，但验证脚本仍调用 Go，部分 Rust 资源仍放在旧 backend 树中。下一步先固化独立 oracle、迁出 codec/证书/模板/manifest/许可资源，再删除旧源码与工具链调用；不能为了让检查通过直接丢弃测试资产。

独立审查还发现原有退出流程在一个清理步骤返回错误后，可能跳过后续独立资源的排空；关闭日志管道也尚未被真实进程测试覆盖。该问题早于本轮，列入后续原生运行时修复，不以正常退出测试代替错误路径验收。

`migration-readiness` 的 40% 是粗粒度无阻塞组件计数，**不是整体迁移完成率**。旧 31.4%/38.31% 同样不再作为当前总体进度。接口全 Rust、构建去 Go、源码去 Go和实体业务验收分开记录；完整目标保持 active。

本轮未生成 DMG，未替换已安装版本，未执行实体卡变更、对外短信或拨号。正常下载、实卡/蓝牙、运营商、音质、升级恢复与长稳仍需各自验收；9eSIM `6982` 仍排除。
