# Iteration 508：串口完整生命周期由 Rust 接管

2026-10-16。本轮已通过完整软件门禁、生产编译和构建输入校验。Rust 接管生产串口的启动、初始化、射频准备、状态采集、事件处理、重连和关闭；全 Rust 后端目标仍在推进，尚未完成。

## 本轮实现

Rust 在打开串口前确立原生管理权、载入短信归档并建立接收者，随后完成设备初始化、绑定当前物理会话的射频配置及状态采集。Go 子进程在此模式下不再创建串口 Manager，不能重复打开设备、读取事件、初始化或执行关闭。独立兼容模式、QMI 及其他仍有实际依赖的 Go 路径保留。

设备状态和健康检查直接读取 Rust 事实，并绑定执行器、物理会话、SIM 代次及射频抑制策略版本。保存号码的异步查询不能在设备断开或身份变化后发布旧结果；策略先改变再恢复时，也不能复用旧元数据。原生管理权不依赖初始化是否已经完成，短信入口不会在启动窗口回落到 Go。

串口事件由 Rust 持续处理。初始化前到达的短信存储通知保留为受限的待扫描存储集合，探测后重新扫描；初始化完成后保持短信接收。短信 PDU 初始化失败只影响短信就绪状态，不阻断已具备的卡片、eSIM 和设备状态能力。

关闭分为停止接受新启动阶段和最终物理关闭两步：先完成已受理的业务、通话及射频清理，再确认原会话已关闭并等待接收者退出。Go 子进程退出不再关闭 Rust 管理的串口；旧会话的终止事实也不会被后续重连改写。
