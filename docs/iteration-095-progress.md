# Iteration 095：USB 短信存储操作迁入 Rust

日期：2026-10-05。全 Rust 后端目标继续执行，尚未完成。所有修改、测试与产物均在 Switch；没有启动生产 App、读取生产短信、接触实体设备、发送短信、操作号卡或生成 DMG。语音目标保持 **EVS 优先、AMR 回退，不使用 PCMA**；当前主机实际能力仍是 AMR-NB mode 7，EVS/AMR-WB 未实现，本轮不计入语音进度。

## 接管范围

Rust 现在执行 USB 短信存储用量查询、SM/ME 清空、单条删除和按发送方删除的完整物理事务。Go 不再生成这些 CPMS/CMGR/CMGD 多命令计划，保留公开接口、VoWiFi/读卡器模式准入、固定 native lease 和本地历史同步。旧 Go 存储事务仅在测试文件中保留，不能据此宣称公开业务入口或全部 Go 已退出。

私有认证 `POST /api/internal/usb-sms/storage-operation` 接收类型化 action 及固定 producer/session/lease；`POST /api/internal/sms/archive/delete-ids` 在一次耐久变更中清理精确历史 ID。两者请求体各限 128 KiB，最多 1500 个删除凭据或历史 ID；物理服务最多允许 8 项已受理操作，生命周期锁等待限 30 秒。公开方法、路径和原有 LOCAL/设备存储区分保留。

## 删除来源与完整确认

- UI 历史 ID 不再直接授权物理存储索引。当前 Rust 快照同时核对开始和结束的 ICCID，将 session、卡身份、存储、全部分段索引及原始 PDU 绑定到随机不透明凭据。缺少完整卡身份的快照仍能展示，不能授予物理删除权限；凭据只在内存预览中出现，不持久化到历史档案。
- 多段短信必须核对全部来源；跨 SM/ME 的重复记录合并来源及历史别名。按发送方选择覆盖私有登记中的所有有效来源，也包括没有合并成完整短信的已识别分片；不能将 500 条 UI 预览当作卡片全部记录。登记最多 1500 组/历史 ID、4096 个来源、1 MiB PDU；超过界限或快照不完整时，不把部分枚举当作按发送方整组删除授权；单条仅允许自身来源完整的有效凭据。
- 事务先保存 CPMS 的三个存储选择，限定操作目标为 SM/ME；每次选择都要求完整成功并回读确认。删除前先预检整组，再逐项复读 ICCID 与 CMGR/PDU；确认 CMGD 成功后再次检查卡身份。位置复用、换卡或旧会话不能凭旧索引继续删除。
- AT 计划预算 120 秒，其中预留 12 秒恢复原选择；真实驱动调用和句柄关闭仍须等待实际完成，这不是强制释放占用的期限。全部操作恢复时均检查原会话/lease，并回读三个存储槽；删除/清空还复核原卡身份，用量查询不执行卡身份读取。清空保留用户明确请求的整存储 CMGD 操作，记录前后实际用量；执行后仍有短信时不报告完全清空。整存储操作可能涵盖命令期间到达的物理短信，不承诺保留这些新记录。
- 完整 `OK`、明确 AT 错误和不完整/断线结果分别处理。无完整终态的快照或事务停止后续实际 I/O，并实际关闭旧句柄；部分已完整采集的内容可用于展示，但不授予新删除凭据。已提交而结果不明的操作不自动重放，不能把 HTTP 取消当作实际硬件已停。

## 并发、历史与兼容边界

采集、耐久归档、预览发布和物理变更共享生命周期锁，避免删除完成后旧采集重新归档。删除前消耗已选凭据；已受理工作由独立任务持有占用，直至实际 I/O、恢复和预览发布结束，关闭流程等待这些任务退出。过期 producer/epoch 不可发布到新预览。

物理确认的预览清理由 Rust 在原操作锁内完成。Go 释放 lease 后不再按相同历史 ID 二次清理 native 预览，避免新会话复用旧 ID 时被旧操作误删。Go 本地缓存按操作前冻结的完整记录匹配，档案只清理操作前存在且已获确认的精确 ID；单条删除不再扩大成删除同发送方全部历史。选择“仅清空设备存储”保留本地档案，清空本机或发送方历史也只作用于初始选定 ID。

已有历史 ID 算法没有重写；它不包含完整卡/session/来源信息，因此仍不能当作全局唯一物理身份。新增凭据及逐项复核解决本轮物理授权问题，不宣称消除了全部历史去重碰撞。原来的串口/读卡器纯本地操作仍可使用；无物理目标的本地会话不会仅因 USB proxy 存在而误进入硬件准入。

Go 公共存储操作期限为 150 秒，Swift 对应操作为 180 秒；网关仅为精确存储路径延长等待，不扩大普通请求默认期限。物理操作部分失败时同步已确认部分并返回明确失败；档案同步错误独立报告，不将“硬件确认、历史未确认”包装成全面成功。
