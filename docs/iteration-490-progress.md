# Iteration 490：IMS 安全套件、注册候选与 3.30 发行

本轮按用户要求收口源码并生成 Switch 3.30 / build 330。应用仍为 SwiftUI 与迁移中的 Rust/Go 后端；未完成全 Rust 改造，不提高此前迁移完成率。

## 源码变更

- Rust IMS 支持精确协商的 AES-CBC、3DES-CBC、NULL 与 HMAC-SHA1-96、HMAC-MD5-96 六种组合；CK/IK 映射和数据帧与 Go 固定向量交叉核验。完整验证 ICV 后解密，认证成功且报文有效后才推进重放窗口。默认仍为 AES/SHA1；未知算法拒绝，原连接完成退役，不回退到明文认证。
- P-CSCF 数字地址自定义配置保留优先级；同地址族内保留多个候选，双栈默认优先 IPv6。复用现有重试策略，仅在前一候选真实清理完成后推进，重新生成 SIP 事务标识，并区分 SIP registrar 与实际传输 gateway。认证后的拒绝不会误作初始节点拒绝。
- 增加生产 Service/LiveDriver 经本地模拟读卡器、SOCKS、IKE/ESP 和保护 REGISTER 到实际退出清理的组合验证。最终通过：定向1/0，4路并行16轮全部成功。
- 组合验证发现原生首代会话生成的短信事务 owner ID 仅 15 字符，低于既有 16 字符约束。已修正 ID 前缀，保留原校验与代次绑定；避免 IMS 注册成功后服务初始化失败。
- 组合并行回归进一步定位到注册完成时唯一取消信号发送端提前释放，导致会话随即误判终止的生命周期缺口；已由同一注册会话持有并校验取消信号，在所有连接和安全资源退出后再释放。显式停止与信号关闭检测保留。
- 新增 des 0.9.0，固定版本和依赖校验值，完整 MIT 许可随应用分发。
