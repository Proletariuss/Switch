# Iteration 129 — 模块语音运行时下载与完整性校验接管

日期：2026-10-08。承接 Iteration 128；全 Rust 后端目标保持进行中。

## 本轮实现与实际归属

语音运行时的 GitHub/relay 下载、有效缓存复用、文件写入、完整性校验和下载进度现在由 Rust 执行。删除 Go 中相应下载器、进度 writer、单文件校验和本地运行时读取实现；Go 公开通话模式 API 保留原来的用户确认、来源选择、硬件前置检查、操作锁与部署编排。

- 新增私有 `GET/POST /api/internal/call-mode/runtime/download`：只接受固定来源与操作编号，GET 只读。POST 同一当前编号幂等；其他编号在下载中返回冲突。实际工作线程持有跨进程文件锁，HTTP 断开不会提前释放下载归属。
- 下载保持固定上游提交、GitHub 直连或两级 relay 顺序、单次两分钟超时、HTTPS 与重定向限制。逐文件核对 Content-Length、实际大小和 SHA-256，经目录句柄定位的临时文件完成写入、权限设置、同步、原子替换和目录同步。某文件失败不会覆盖其旧内容，前面已经验证并提交的文件仍可复用。
- 新增私有 `GET /api/internal/call-mode/runtime/verify`。全部六个文件通过才报告就绪；下载字节数只累计哈希正确的文件。这修正了旧 Go 只凭文件大小计入进度的情况。
- 部署端点也先校验全部六个文件，再返回三个 `deploy=true` 的文件。文件读取拒绝符号链接和非普通文件，FIFO 不会阻塞；文件校验在有并发上限的 blocking worker 中执行。
- 新增一份 Go/Rust 共同嵌入的 `voice-runtime-manifest.json`，统一版本、固定提交、内核、六个文件的大小、哈希、权限及部署标记；总大小为 1,080,625 字节。
- Go 适配只提交一次下载 POST，响应丢失时通过 GET 核对相同操作编号、来源、版本与大小。只有明确完成且再次全量校验成功，才进入原有 ADB 部署。未知结果、错误或超时均不重发 POST、不继续部署。
