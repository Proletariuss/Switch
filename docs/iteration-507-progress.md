# Iteration 507：串口 eSIM/LPA 原生执行与事务收尾

2026-10-16。本轮源码接线、完整软件门禁、Rust 生产编译和输入集合校验通过。串口 eSIM 的公开读取、健康检查、改名、删除、切卡和下载任务已进入 Rust 原生执行路径；完整串口生命周期及最终 Go 退出仍未完成。

## 本轮实现

串口选择后，Rust 在启动兼容 Go 子进程前取得稳定的 eSIM 管理权。Go 不再创建该设备的 LPA manager，也不能通过旧公开/私有接口或普通 AT 写入口发起逻辑通道操作。独立兼容模式及其他 transport 继续按既有条件处理，不以普通端点由 Rust 响应就宣称完全无 Go。

Rust actor 以执行器实例、物理串口会话和 SIM 代次绑定完整 CCHO/CGLA/CCHC 事务，包括网络等待和下载确认。即使 HTTP 等待者取消，执行者仍持有资源直至实际关闭；无法确认关闭时隔离原会话，不在新连接上重试或猜测清理。旧关闭请求入队时冻结原会话，事务释放后重新唤醒期间已到达的 CMTI 工作。

列表、健康、切卡、改名、删除及下载复用现有 Rust eUICC/LPA 实现。无启用 Profile、无短信初始化时仍能管理 eUICC。缓存与返回结果绑定同一串口/SIM；健康推断只使用同一次事务的有效身份，不改变短信就绪状态。保留默认射频抑制、-999 信号和飞行模式投影。

公开接口回归发现“操作完成后缓存刷新重新占用射频”的窗口。现将最终刷新置于原 reservation 内，实际释放后才发布终态或返回 HTTP 成功；随后立即删除的严格用例通过，不以等待或放宽 busy 结果掩盖问题。

## 剩余范围

Go 仍供应串口启动、初始化接线、旧事件读取、状态缓存及停止。原生串口 AKA/VoWiFi 接线是仍待补齐的既有能力缺口；本轮没有把 USB 的 IMS 能力错误标为串口已完成。QMI/其他兼容路径及 Go 构建、运行、嵌入依赖仍保留。

下一步按[完整串口生命周期评估](../../build/reports/iteration-508-serial-lifecycle-assessment.md)迁移原生启动/事件处理/完整元数据/停止与重连，接入稳定原生 radio producer，并移除 Go Manager 的生产构造根。Go 退出时不能关闭原生串口；不能只替换 open 而留下 Go 事件读取或状态供应。
